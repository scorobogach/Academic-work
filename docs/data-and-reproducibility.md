# Данные и воспроизводимость

Этот раздел — про единственное, что нельзя подделать текстом: про то, что
результат действительно получен из данных.

## Разделение: сырьё, производное, текст

| Слой | Примеры | Правило |
|---|---|---|
| **Сырые данные** | показания приборов, выгрузки, анкеты, логи | неизменяемы; правка только через новую версию |
| **Производное** | очищенные таблицы, агрегаты, `results.json`, фигуры | пересобираются из сырья одной командой |
| **Текст** | рукопись, таблицы в `.tex` | числа берутся **только** из производного, никогда не вбиваются руками |

Руками вбитое число в таблицу рукописи — ошибка, которая рано или поздно
разойдётся с данными. Гейт G5 существует именно для её отлова.

## Манифест данных

```bash
# analysis/manifest.sha256 — создаётся один раз, обновляется при изменении сырья
find data/raw -type f -exec sha256sum {} + | sort -k2 > analysis/manifest.sha256

# проверка перед каждым пересчётом
sha256sum -c analysis/manifest.sha256
```

Хеш манифеста записывается в журнал (`journal.append --type file`). Если
сырьё изменилось, появляется новая запись — со старой версией и причиной.

## Окружение и seed

- lock окружения: `renv.lock` / `requirements.txt` с версиями / `pixi.lock` /
  `environment.yml` / Docker-образ с тегом;
- версия интерпретатора и ключевых библиотек фиксируется в рукописи;
- `seed` для всего стохастического (разбиение, бутстрап, инициализация);
- дата запуска и хеш кода — в журнале и в `analysis/results.json`.

## Одна команда

```bash
# analysis/run_all.sh — без аргументов, без ручных шагов
set -euo pipefail
python3 analysis/01_clean.py      # data/raw -> data/clean
python3 analysis/02_analyze.py    # data/clean -> analysis/results.json
python3 analysis/03_figures.py    # results.json -> figures/*.pdf
python3 analysis/04_tables.py     # results.json -> tables/*.tex
sha256sum -c analysis/manifest.sha256
```

```bash
make reproduce        # вызывает analysis/run_all.sh
```

Правило G6: рукопись не собирается, пока эта команда не выполняется от начала
до конца на чистом checkout и не даёт те же числа.

## Что делает этот репозиторий

- **G5**: сверяет числа в тексте с `results.json` (детерминированно).
- **G6**: требует `make reproduce` + манифест + lock окружения + seed.
- **Журнал**: хранит хеши сырых данных, версии кода и артефактов.

## Чего он не делает и не может

- не доказывает, что данные собраны именно так, как описано (для этого —
  протокол, журналы эксперимента, этика/IRB);
- не проверяет корректность статистического метода (для этого —
  рецензирование и, желательно, предрегистрация);
- не заменяет независимое воспроизведение другим исследователем.

## Минимум, который стоит сделать даже без всяких инструментов

1. Сырые данные — в отдельный каталог, read-only, с манифестом.
2. Один скрипт, который пересчитывает всё из сырья.
3. Версии пакетов и seed записаны.
4. Ни одного числа в тексте, которого нет в выводе скрипта.
5. Хеш данных зафиксирован в истории версий.

## Предрегистрация и registered reports (сильно рекомендуется)

Если ваша область это поддерживает: предрегистрация фиксирует гипотезы,
дизайн и план анализа **до** получения результатов. Это единственный
инструмент, который защищает от «подгонки» постфактум — никакой гейт это
не заменит, потому что гейт видит уже готовый текст.

## Статистика: быстрые самопроверки

Полноценная проверка метода — задача рецензента, но автоматически стоит
проверять: совпадение n между разделами и таблицами, соответствие степеней
свободы указанному тесту, согласованность доверительных интервалов и p-значений,
единицы измерения, знаки эффектов. Большинство ошибок в статьях — из этой
группы, и почти все они детерминированно проверяемы.
