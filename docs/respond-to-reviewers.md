# Ответ рецензенту: рабочий процесс

Ответ на рецензию — самая недооценённая часть процесса, и именно там чаще
всего возникают новые фактические ошибки: правишь одно, ломаешь другое.

## Принцип

Каждое замечание рецензента — это либо **новое утверждение**, либо **новое
ограничение**, либо **новая задача на данные**. Всё это уже умеют реестры:
не нужно вести ответ в отдельном документе «вручную».

## Поток

```
отзыв рецензента
   │
   ├─ парсинг по пунктам: R1.1, R1.2, R2.1 ...
   │
   ├─ каждый пункт → decisions.upsert (вопрос: что делать; reopen_if)
   │
   ├─ если пункт требует нового источника
   │     └─ evidence.upsert + claims.upsert (verdict: unverifiable → supported)
   │
   ├─ если пункт требует пересчёта
   │     └─ analysis/ → results.json → make reproduce → G5 → G6
   │
   ├─ правка текста → G0 G1 → G2 (верность) → G3 G4
   │
   └─ ответ → templates/response-to-reviewers.md + gate-record
```

## Структура пункта ответа

| Поле | Смысл |
|---|---|
| `id` | `R1.1` — номер рецензента и пункта |
| `quote` | цитата замечания (verbatim) |
| `decision_id` | ссылка на решение, принятое по замечанию |
| `action` | что сделано: правка / пересчёт / добавлен источник / аргументированный отказ |
| `locator` | где в рукописи: секция, страница, строка |
| `evidence_refs` | источники, добавленные в ответ на замечание |
| `gate_run_id` | прогон гейта, подтверждающий правку |
| `status` | `done` / `partial` / `declined` |

Шаблон: [../templates/response-to-reviewers.md](../templates/response-to-reviewers.md).

## Типовые ловушки

| Ловушка | Как ловится |
|---|---|
| Правка ответа разошлась с таблицей | G5 (числа) + G6 (пересборка) |
| Новый абзац содержит утверждение без источника | G1 (`UNSOURCED`) + G4 |
| Добавленная ссылка не подтверждает новое утверждение | G4: локатор + verbatim |
| Сокращение выбросило важную оговорку | G2: сверка с предыдущей версией |
| Правка внесла невидимые символы | G0 |
| Обещали «добавили анализ», но скрипта нет | G6: `make reproduce` |

## Отказ от правки

Отказ — нормальный и уважаемый ответ, если он обоснован. Требование: в
`decisions` фиксируется, почему именно вы не согласны, на что опираетесь
(источник/данные/метод) и что стало бы условием пересмотра (`reopen_if`).
Отказ без обоснования превращается в «автор не ответил».

## После отправки

- сохраните версию рукописи и ответа: тег + хеш в журнале;
- обновите `decisions`: что из обещанного сделано, что отложено;
- запишите уроки (тип «lesson»): повторяющиеся замечания рецензентов —
  лучший источник правил для ваших гейтов.
