# Формат полного журнала

Журнал — append-only последовательность JSON-объектов, по одному в строке
(JSONL), разбитая по месяцам: `journal/YYYY-MM.jsonl`.

## Запись

```json
{
  "v": 1,
  "id": "01J9Z8QW3E4R5T6Y7U8I9O0P",
  "ts": "2026-09-21T10:15:03.221Z",
  "session": "s-2026-09-21-01",
  "project": "thesis-ch4",
  "actor": "agent:claude-code",
  "type": "gate_run",
  "refs": {"parent": "01J9Z8...", "artifact": "sha256:9f2c..."},
  "payload": {
    "gate": "G3_bibliography",
    "verdict": "fail",
    "blocking": true,
    "findings": [{"code": "BIB-MISSING", "ref": "ghost2021"}]
  },
  "prev": "sha256:1a4e...",
  "hash": "sha256:7bd0..."
}
```

| Поле | Смысл |
|---|---|
| `v` | версия формата; при изменении правил хеширования версия инкрементируется |
| `id` | ULID: сортируем по времени, уникален без координации |
| `ts` | UTC, миллисекунды, ISO-8601 |
| `session` | идентификатор сессии агента; связывает события одного диалога |
| `project` | проект/глава/рукопись |
| `actor` | `human`, `agent:claude-code`, `tool:citecheck`, `script:gates` |
| `type` | см. ниже |
| `refs` | ссылки: `parent`, `artifact`, `claim_id`, `source_id`, `conv` |
| `payload` | произвольный JSON — смысл события |
| `prev` | хеш предыдущей записи (у первой — пустая строка) |
| `hash` | `sha256(canonical_json(запись без hash) + prev)` |

**Каноническая сериализация** (важно для воспроизводимости хеша): ключи
отсортированы, разделители `,` и `:`, `ensure_ascii=False`, UTF-8.
Реализация: `academic_journal/journal.py: canonical_json`.

## Типы событий

| type | Когда |
|---|---|
| `message` | сообщение человека или ответ агента (текст целиком) |
| `tool_call` / `tool_result` | вызов MCP-инструмента или внешнего CLI и его результат |
| `file` | снимок или хеш файла (рукопись, данные, скрипт) |
| `claim` | утверждение зарегистрировано или изменено |
| `evidence` | источник добавлен или проверен |
| `decision` | решение принято, изменено или отменено |
| `gate_run` | прогон гейта с вердиктом и стоимостью |
| `note` | заметка, наблюдение, вопрос без решения |
| `signoff` | человеческое подтверждение (этап G7) |

## Хеш-цепочка

```
record[n].prev  == record[n-1].hash
record[n].hash  == sha256(canonical(record[n] без hash))
```

Проверка: `make journal-verify` (или `python3 scripts/journal_cli.py verify`).
Обнаруживаются:

- подмена содержимого (`hash mismatch`);
- удаление строки (`chain broken`);
- расхождение со служебным состоянием (`state mismatch`).

Цепочка **не защищает** от удаления всего журнала целиком и от «переписать
журнал заново с нуля». От этого защищает внешняя фиксация:

```bash
python3 scripts/journal_cli.py manifest > MANIFEST.sha256   # sha256 каждого файла
git tag -s journal-2026-09-21                                # подпись
# опционально: депозит архива в Zenodo → DOI
```

## Что попадает в журнал, а что нет

**Пишем:** текст сообщений, аргументы и результаты инструментов, хеши файлов,
вердикты гейтов, стоимость и длительность прогонов, решения с обоснованием.

**Не пишем:** значения API-ключей, пароли, содержимое чужих закрытых материалов
целиком (только хеш и ссылку), персональные данные участников исследования
(только pseudonymised ID; сырые данные — в отдельном защищённом хранилище).

## Ретеншн и размер

Оценка: активный день работы с агентом — 1–5 МБ. Год — 0.3–1.5 ГБ. Это немного,
поэтому **не удаляйте старые записи**: журнал ценен именно полнотой.
Если объём критичен, дедуплицируйте файлы (в журнал пишите хеш + путь),
а не сообщения. Срок хранения и правила удаления —
[privacy-and-legal.md](privacy-and-legal.md).
