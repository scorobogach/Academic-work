# Справочник по гейтам

Гейт — это проверка с однозначным вердиктом, отчётом и (для части гейтов)
блокирующим статусом. Отчёт всегда пишется на диск: «проверено» должно быть
файлом, а не утверждением в чате.

## Сводка

| # | Гейт | Команда | Кто | Блокирует при |
|---|---|---|---|---|
| G0 | `hygiene` | `make gate-hygiene` | скрипт | невидимые Unicode, bidi-контролы |
| G1 | `style` | `make gate-style` | скрипт | `UNSOURCED` всегда; `score < 90` |
| G2 | `fidelity` | второй агент | агент | изменены числа, цитаты, оговорки, выводы |
| G3 | `bibliography` | `make gate-bib` / `make gate-bib-online` | скрипт (+сеть) | ссылка отсутствует в `.bib`, DOI не найден, название не совпадает |
| G4 | `claim_alignment` | `make gate-claims` / `make gate-quote` | скрипт + человек | нет цитаты/файла; цитата не совпадает; вердикт ≠ `supported` |
| G5 | `numbers` | `make gate-numbers` | скрипт | настраивается (по умолчанию предупреждение) |
| G6 | `reproducibility` | `make reproduce` | скрипт/человек | таблицы не пересобираются из сырых данных |
| G7 | `disclosure` | `make disclosure` + человек | скрипт + человек | нет лога ИИ, disclosure, подписи, конфликта интересов |
| G8 | `figures` | `make gate-figures` | скрипт | нет файла рисунка, нет подписи, дубль метки |
| GX | `canary` | `make canary-run` | скрипт | recall контура < 0.8 |

Коды возврата CLI: `0` — не блокирует, `1` — блокирует. Это позволяет встроить
гейт в pre-commit или CI без дополнительной обвязки.

## G0 — гигиена

Убирает технический брак, который приносит текст из буфера обмена и от моделей:
zero-width-пробелы (`U+200B`–`U+200F`, `U+2060`, `U+FEFF`, `U+00AD`),
bidi-управляющие символы (`U+202A`–`U+202E`, `U+2066`–`U+2069`),
нестандартные пробелы. Информационные сообщения: тире как маркер списка,
неразрывный пробел внутри числа.

```bash
python3 scripts/journal_cli.py hygiene --file draft.tex --fix   # с .bak
make gate-hygiene
```

## G1 — стиль

Считает «воду», а не authorship. Что проверяется:

- **UNSOURCED (блокирующий):** «исследования показывают», «эксперты считают»,
  «как известно», «многие авторы», `studies show`, `experts agree`.
- шаблонная лексика, пустые обороты, канцеляризмы, filler, sweeping-слова;
- деепричастные «хвосты» (аналог trailing `-ing`): «…, подчёркивая значимость»;
- negative parallelism, ложная субъектность («данные говорят»), нагнетание
  значимости, нагромождение hedge-оборотов;
- ритм: 4 коротких предложения подряд, 3 длинных подряд, тире на 1000 слов.

Счёт: `score = 100 − (Σ весов / число слов) × 1000`, порог задаётся в
`config/gates.json`. Словари — `config/style-rules.ru.json`: **настройте их под
свою дисциплину.** Ложные срабатывания дороже пропущенных: если оборот нормален
для вашего стиля — удалите его из словаря.

Игнорируются: код в блоках ``` ``` ``` и `` ` ``, Markdown-цитаты (`>`), HTML-комментарии.
Точечное исключение на строке: `<!-- slop-ignore CODE -->`.

## G2 — верность правки

Скрипт здесь бессилен: он не отличит правду от выдумки. Порядок:

1. агенту-редактору даётся текст на правку;
2. **второй** агент получает оригинал и правку, но **не** рассуждения первого;
3. проверяются: числа, цитаты, имена, оговорки, сила утверждений, выводы;
4. найденные расхождения — список, а не автоматические правки;
5. результат фиксируется: `python3 scripts/journal_cli.py gate-record --file report.json`.

Опыт `anti-ai-slop` полезен как предупреждение: правки, получающие 100/100 на
линтере, всё равно содержат детали, которых не было в оригинале. Поэтому G2
обязателен, даже если G1 идеален.

## G3 — библиография

Офлайн (по умолчанию): каждый ключ `\cite{...}` есть в `.bib`; у записи есть DOI
или URL; заполнены author/title/year.
Онлайн (`--online`): сверка DOI через Crossref, сравнение начала названия.

```bash
make gate-bib                       # офлайн
make gate-bib-online                # + Crossref
python3 scripts/journal_cli.py extract --tex main.tex --bib refs.bib
```

Смысл проверки: источник **существует**. То, что он подтверждает именно ваше
утверждение, — это уже G4.

## G4 — соответствие утверждения источнику

Проверка делится на автоматическую часть (сверка цитаты) и человеческую
(подтверждает ли фрагмент именно ваше утверждение). Автоматизировано первое.

```bash
make gate-claims                                   # весь реестр: нужны quote + source_id + файл
make gate-quote SOURCE=literature/smith2020.pdf QUOTE="…" LOCATOR="p. 7"
python3 scripts/journal_cli.py run-gate G4 --db ~/.academic/journal.db --project thesis
```

Уровни совпадения цитаты:

| Уровень | Что означает | Действие |
|---|---|---|
| `exact` | цитата найдена в тексте источника дословно | ок |
| `normalized` | совпала после нормализации: кавычки, тире, переносы, неразрывные пробелы, пунктуация | ок |
| `fuzzy` | совпадение по словам выше порога (`min_fuzzy_ratio`, по умолчанию 0.8) | warning: сверить вручную |
| `mismatch` | ниже порога | error |
| `unverifiable` | файл недоступен или текст не извлечён | error |

**Честность важнее зелёного статуса.** Если PDF — скан или использует CID-шрифты,
текст не извлекается: проверка возвращает `unverifiable`, а не «похоже». Порядок
извлечения: `pdftotext` (poppler) → собственный извлекатель на stdlib (`zlib`) →
готовый `.txt`/`.md` рядом с источником. Для сканов работает только ручная проверка
или OCR вне пайплайна.

Человеческая часть — решить, подтверждает ли найденный фрагмент именно ваше
утверждение, и выставить вердикт:

| Поле | Требование |
|---|---|
| `source_id` | обязателен для empirical/methodological |
| `quote` | цитата слово в слово |
| `quote_locator` | страница / абзац / номер строки — обязателен; при расхождении более чем на 1 страницу гейт пишет предупреждение |
| `verbatim_match` | `exact` / `normalized` / `fuzzy` / `mismatch` / `unverifiable` |
| `verdict` | `supported` / `partially_supported` / `not_addressed` / `unverifiable` / `self_computed` / `contradicted` |

Блокирующие вердикты: `not_addressed`, `unverifiable`, `contradicted`.
Шаблон: [../templates/claim-audit.md](../templates/claim-audit.md).

## G5 — числа

Каждое число в тексте **и в таблицах** сверяется с машиночитаемыми результатами
(`analysis/results.json`). Это детерминированный пересчёт, а не «похоже ли».

```bash
make gate-numbers                   # --values analysis/results.json
```

Игнорируются: числа в командах `\cite`, `\ref`, `\label`, `\includegraphics`,
в контексте «рисунок/таблица/приложение/ГОСТ/№». Поддерживаются разделители
разрядов (`1 234`) и десятичная запятая (`0,031`). Настраивается в
`config/gates.json`: `allow`, `ignore_context`, `blocking`, `check_tables`.

Коды находок: `NUM-UNTRACED` (числа нет в результатах), `NUM-TABLE-UNTRACED`
(то же в таблице), `NUM-UNUSED` (результат не упомянут в тексте, info).

Ловит типичную ошибку: вывод верный, а число из соседней строки таблицы.

## G6 — воспроизводимость

```bash
make reproduce                      # analysis/run_all.sh + environment.lock
```

Рукопись не собирается, пока из сырых данных одной командой не пересобираются
все таблицы и фигуры и не совпадает манифест. Подробности:
[data-and-reproducibility.md](data-and-reproducibility.md).

## G7 — раскрытие и подпись

Машинный лог использования ИИ по секциям → раздел disclosure → конфликт интересов
→ человеческая подпись [../templates/sign-off.md](../templates/sign-off.md).
Без файла подписи финальный гейт не проходит.

## G8 — рисунки и подписи

Подпись к рисунку проверяют реже основного текста, хотя числа и утверждения там
бывают не менее важными.

```bash
make gate-figures                    # MANUSCRIPT + VALUES
```

| Код | Что проверяет | Важность |
|---|---|---|
| `FIG-FILE-MISSING` | файл рисунка существует (путь ищется с расширениями pdf/png/svg/eps/…) | error |
| `FIG-NO-CAPTION` | у рисунка есть подпись | error |
| `FIG-DUP-LABEL` | метки уникальны | error |
| `FIG-NO-LABEL` | у рисунка есть `\label` | warning |
| `FIG-UNCITED` | рисунок упомянут в тексте через `\ref` | warning |
| `FIG-NUM-UNTRACED` | число в подписи есть в `results.json` | warning |
| `FIG-STALE` | рисунок новее `results.json` (пересобран после изменения данных) | warning |

Эвристика «число относится к рисунку/таблице» смотрит только на 40 символов
**слева** от числа и 8 справа: иначе любое число, оказавшееся рядом со словом
«рисунок», пропадало бы из проверки.

Хеши найденных файлов рисунков попадают в отчёт — это часть provenance.

## Синхронизация .bib ↔ реестр источников

```bash
make bib-import        # manuscript/refs.bib → реестр evidence (metadata_verified=0)
make bib-export        # проверенный реестр → manuscript/refs.verified.bib
```

- **Импорт** (`source_id` = cite key) заполняет author/title/venue/year/doi и
  угадывает `trust_tier`: `article` → `primary`, `eprint`/arXiv/bioRxiv →
  `preprint`, `misc` без DOI → `gray`. Импорт **не** выставляет
  `metadata_verified`: запись из .bib — заявка, а не подтверждение.
- **Экспорт** по умолчанию берёт только проверенные записи, поэтому в рукопись
  можно вернуть библиографию, в которой нет ни одной непроверенной ссылки.
  Флаг `--all` снимает фильтр.

## Canary-тест контура (GX, раз в месяц и перед сдачей)

Не для рукописи, а для самого пайплайна. Полностью офлайн и детерминировано:

```bash
make canary-run MANUSCRIPT=manuscript/main.tex BIB=manuscript/refs.bib \
                 VALUES=analysis/results.json
```

1. В копию черновика (`*.canary.tex`) подмешиваются: 5 утверждений без источника,
   3 несуществующие ссылки `\cite{canaryghostN}`, 1 число, которого нет в `results.json`.
2. По копии прогоняются G1, G3, G5 (их отчёты не перезаписывают рабочие).
3. Считается recall: доля подмешанного, что гейты реально нашли. Манифест
   ожидаемых находок — `*.canary.json`.
4. Recall < 0.8 — гейт `GX_canary` блокирующий: «зелёным» отчётам контура
   больше нельзя доверять, причины разбираются.

Отдельные шаги: `make canary` (подмешать) и `make canary-check` (посчитать recall
по готовым отчётам). To же через CLI: `canary --file … --seed 42` и
`canary-check --manifest … --g1 … --g3 … --g5 …`.

Замер полезно хранить рядом с отчётами: это единственный способ отличить
работающий контроль от декоративного.

## Экспорт и disclosure

```bash
make export        # export/{evidence,claims,decisions,gates}.{csv,md}
make disclosure    # ai-disclosure.md, собранный из записей kind=ai_use журнала
```

Экспорт — это доказательная база: CSV/Markdown прикладываются к рукописи,
вкладываются в ответ рецензенту и передаются соавторам, которые не пользуются
инструментом. Disclosure собирается из машиночитаемого лога, поэтому
формулировка всегда соответствует тому, что реально делалось.
