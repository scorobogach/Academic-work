# Протокол сессии

Цель: начать работу за минуту, не пересказывая историю, и закончить её так,
чтобы следующая сессия началась так же быстро.

## Старт сессии (обязательно)

```bash
make resume                      # или: python3 scripts/journal_cli.py resume --out CONTEXT.md
```

Контекст-пак собирается **из БД детерминированно** (не моделью):

1. активные решения (`decisions.status = active`) с обоснованием и условием пересмотра;
2. блокирующие утверждения (`claims.status = blocking`);
3. счётчики утверждений по статусам + список `open`;
4. статус последних прогонов гейтов (по одному на гейт);
5. автоматически выведенные следующие действия;
6. реестр источников.

Каждый пункт снабжён идентификатором (`claim_id`, `decision_id`, `run_id`).
Нужна деталь — достаётся точечно:

```bash
python3 scripts/journal_cli.py search --query "дизайн выборки" --indexed
```

**Правило контекста:** в окно модели попадает только выжимка со ссылками,
никогда — весь архив. Архив всегда сохранён; в контекст извлекается релевантное.

### Слова для агента (вставьте в CLAUDE.md / AGENTS.md проекта)

```markdown
## Начало сессии
1. Вызови MCP-инструмент `resume.build` и прочитай контекст-пак.
2. Не переспрашивай о решениях со статусом active — они в пакете.
3. Если в пакете есть blocking-утверждения, начни с них.

## Во время сессии
- Каждое фактическое утверждение сначала заносится в `claims` со статусом open.
- Нет источника — утверждение получает verdict `unverifiable` и в текст не идёт.
- Любое действие, меняющее рукопись, фиксируется через `journal.append`.

## Конец сессии
- Записать новые решения через `decisions.upsert` (обязательно поле reopen_if).
- Прогнать G0 и G1 по изменённым файлам и записать результат.
- Обновить память (Engram/agentmemory) — только производные выводы со ссылкой на journal_id.
```

## В работе

| Событие | Что делать |
|---|---|
| Появилось фактическое утверждение | `claims.upsert` → `verdict: unverifiable`, `status: open`. Проверено → обновить вердикт и локатор |
| Нашли источник | `evidence.upsert` (DOI/PMID/URL, `trust_tier`, `pdf_sha256`, `local_path`) |
| Приняли решение | `decisions.upsert` с `rationale`, `rejected`, `reopen_if` |
| Прогнали гейт | `make gate-*` или MCP `gates.record` — с вердиктом, стоимостью и путём к отчёту |
| Изменили рукопись | `journal.append` с типом `file` и хешем версии |
| Агент сделал правку | гейт **G2**: сверить числа, цитаты, оговорки, выводы с оригиналом |

Мини-правило, экономящее больше всего времени: **закрытое решение не обсуждается
повторно без выполнения условия `reopen_if`.** Если вернулись к вопросу —
сначала зафиксируйте, какое условие сработало.

## Финал сессии

1. `make gates` по изменённым файлам.
2. Консолидация памяти: что нового мы теперь знаем? (3–7 пунктов, не больше.)
   Каждый пункт — со ссылкой на `journal_id`.
3. `make journal-verify` — цепочка цела.
4. `make resume --out CONTEXT.md` — если работа передаётся или продолжается завтра.

## Анти-паттерны

| Паттерн | Почему плохо | Что делать |
|---|---|---|
| «Сделай саммари всего проекта и положи в память» | саммари теряет нюансы и не доказуемо | в память — только решения/ограничения + `journal_id`; полный контекст остаётся в журнале |
| Копировать весь архив в контекст | дорого, модель теряет фокус | выжимка + точечный поиск по `id` |
| Править рукопись без записи в журнал | через неделю невозможно восстановить, почему так | `journal.append` на каждое изменение |
| Верить «зелёному» гейту без canary-теста | гейт может молча сломаться | раз в месяц подмешивать ложные утверждения и ссылки |
