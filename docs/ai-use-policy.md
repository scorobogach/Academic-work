# Политика использования ИИ и раскрытия

Позиция проекта: **цель — точность и ясность, а не маскировка.** Инструменты
стиля в этом репозитории предназначены для удаления технического брака и
пустых оборотов, а не для того, чтобы скрыть факт использования модели.

## Почему не удаляем водяные знаки и не обходим детекторы

1. **Это не повышает достоверность.** Работа становится не более проверяемой
   от того, что маркер снят.
2. **Это риск для вас.** Журналы и вузы требуют раскрытия использования ИИ;
   удаление C2PA/SynthID-маркеров происхождения прямо противоречит таким
   требованиям и может быть квалифицировано как искажение provenance.
3. **provenance — это актив, а не проблема.** Сохранённая история правок
   защищает автора: она показывает, что именно сделано человеком, а что —
   с помощью модели.

Поэтому в пайплайне нет `watermarks-remover` и аналогичных инструментов
(см. [../NOTICE.md](../NOTICE.md)). Вместо этого — хранение provenance и
машиночитаемый лог использования ИИ.

## Разрешено

| Что | Условие |
|---|---|
| Поиск и систематизация литературы | источники проверяются (G3/G4), а не принимаются на веру |
| Редактура: стиль, структура, сокращение | правка проходит G2 (верность смыслу) |
| Вычитка невидимых символов и типичных артефактов | G0 |
| Генерация кода анализа | код воспроизводит результаты; версии и seed зафиксированы (G6) |
| Подготовка disclosure-раздела | текст проверен человеком |
| Обсуждение дизайна и интерпретации | решение и его обоснование записаны в `decisions` |

## Запрещено

| Что | Почему |
|---|---|
| Фабрикация ссылок, цитат, чисел, данных | прямая фальсификация |
| Генерация разделов «Результаты» и «Обсуждение» без проверки человеком | интерпретация — ответственность автора |
| Использование текста, написанного моделью, без disclosure там, где disclosure требуется | нарушение правил журнала/вуза |
| Удаление provenance-маркеров происхождения | искажение атрибуции |
| Передача неопубликованного текста в облачные сервисы без оценки риска | утрата контроля над материалом |

## Лог использования ИИ (машиночитаемый)

Ведётся по секциям рукописи. Формат записи в журнале:

```json
{
  "type": "note",
  "actor": "human",
  "payload": {
    "kind": "ai_use",
    "section": "Методы",
    "authorship": "human_draft_model_edit",
    "model": "claude-opus-4.5",
    "tasks": ["стилистическая правка", "проверка согласованности терминов"],
    "human_verification": ["числа сверены с results.json", "цитаты сверены с PDF"],
    "disclosure_required": true,
    "date": "2026-09-21"
  }
}
```

Значения `authorship`: `human_only` · `human_draft_model_edit` ·
`model_draft_human_edit` · `model_draft_human_rewrite` · `model_generated_unchecked`
(последнее — блокирующее для сдачи).

## Шаблоны формулировок

Готовые варианты для раздела «AI disclosure» — в
[../templates/ai-disclosure.md](../templates/ai-disclosure.md). Правило:
формулировка выбирается под требования конкретного журнала/вуза, а не
наоборот; при отсутствии требований disclosure всё равно лучше сделать —
это дешевле, чем объясняться потом.

## Практический вывод

Работа с ИИ не скрывается, а **документируется**. У вас есть журнал, где
записано, кто и что делал; есть лог по секциям; есть отчёты гейтов. Этого
набора достаточно и для ответа рецензенту, и для разбирательства, если
вопросы возникнут позже.
