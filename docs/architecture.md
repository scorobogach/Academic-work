# Архитектура

## Принцип

Один источник истины (неизменяемый журнал), несколько производных индексов
(SQLite-реестры, семантическая память, саммари). Любой индекс можно пересобрать
из журнала; журнал нельзя восстановить из индексов.

```
                    ┌──────────────────────────────┐
   человек / агент  │  Claude Code · Codex · Cursor │
                    └───────────────┬──────────────┘
                                    │ MCP (stdio, JSON-RPC 2.0)
                    ┌───────────────▼──────────────┐
                    │   academic-journal MCP-сервер │
                    │   journal · claims · evidence │
                    │   decisions · gates · resume  │
                    └───────┬───────────────┬──────┘
                            │               │
              ┌─────────────▼──┐   ┌────────▼─────────────┐
              │ ЖУРНАЛ (истина)│   │ РЕЕСТРЫ (структура)  │
              │ journal/*.jsonl│◄──┤ SQLite + FTS5         │
              │ append-only    │   │ evidence claims       │
              │ hash-chain     │   │ decisions gates       │
              └───────┬────────┘   └────────┬─────────────┘
                      │                     │
           manifest.sha256          CSV / Markdown-экспорт
           git tag · Zenodo DOI     (вложение в рукопись)
                      │
              ┌───────▼─────────────────────────────────┐
              │ ПАМЯТЬ (производная)                     │
              │ Engram / agentmemory · решения, уроки,   │
              │ ограничения — всегда с ссылкой journal_id │
              └──────────────────────────────────────────┘

   Детерминированные гейты (G0 G1 G3 G5) ──► reports/gates/*.json ──► gates.record
   Модельные и человеческие гейты (G2 G4 G6 G7) ─────────────────► gates.record
```

## Слои

### 1. Журнал — `journal/YYYY-MM.jsonl`

Одна JSON-строка на событие. Каждая запись хранит `prev` (хеш предыдущей) и
`hash` (свой собственный). Изменение или удаление любой строки ломает цепочку —
`make journal-verify` это обнаруживает. Формат: [journal-format.md](journal-format.md).

Зачем: «весь диалог сохраняется» — это требование к полноте, а не к поиску.
Полнота обеспечивается append-only, а не качеством саммари.

### 2. Реестры — SQLite

Поисковый индекс журнала (`events` + FTS5) плюс четыре реестра, с которыми
работает человек: `evidence`, `claims`, `decisions`, `gates`. Реестры —
единственная часть системы, которую предполагается редактировать.
Схема: [../schemas/](../schemas/), SQL: [../scripts/academic_journal/db.py](../scripts/academic_journal/db.py).

### 3. Память — производная

Engram или agentmemory хранят только то, что полезно между сессиями: решения,
ограничения, уроки, терминологию проекта. Каждая запись памяти обязана ссылаться
на `journal_id` — иначе она непроверяема. Подробности: [memory-architecture.md](memory-architecture.md).

### 4. Гейты

Детерминированные (G0, G1, G3, G5) реализованы в коде и работают без сети и модели.
Модельные (G2, G4) выполняются агентом, человеческие (G6, G7) — человеком; их
результат фиксируется через `gates.record`, чтобы «проверено» стало фактом,
а не утверждением. Подробности: [gate-reference.md](gate-reference.md).

## Поток работы

```
идея → план → поиск литературы → черновик → [G0 G1] → правка → [G2] →
проверка ссылок [G3] → проверка утверждений [G4] → числа [G5] →
воспроизведение [G6] → раскрытие и подпись [G7] → сдача
```

Каждый шаг пишет события в журнал; каждый гейт оставляет отчёт в
`reports/gates/<gate>.json` и запись в таблице `gates`.

## Почему именно так

| Решение | Альтернатива | Почему выбрано |
|---|---|---|
| JSONL + хеш-цепочка вместо БД как истины | «Просто писать в SQLite» | SQLite-файл можно отредактировать незаметно; цепочка делает правку обнаружимой, а файлы журнала — обычный текст, который читается через 20 лет |
| Свои реестры вместо «умной памяти» | Память, извлекающая факты автоматически | Извлечённые факты теряют нюанс и не доказательство; реестр заполняется осознанно и проверяемо |
| stdlib only | MCP SDK, pydantic, SQLAlchemy | Журнал должен открываться без установки чего-либо; минимум зависимостей = минимум риска |
| SQLite по умолчанию | PostgreSQL | Один файл, офлайн, бэкап копированием. Переход на Postgres — смена DSN, см. [storage-decision.md](storage-decision.md) |

## Интеграция с внешним research-пайплайном

Этот репозиторий **не заменяет** research-пайплайн, а журналирует его.
Рекомендуемая связка: `Imbad0202/academic-research-skills` ведёт стадии
исследование → черновик → рецензия → финализация; каждый его шаг
сопровождается записью в журнал, а его integrity-гейты дополняются нашими
G0–G7. См. [research-workflow.md](research-workflow.md) и [tool-selection.md](tool-selection.md).
