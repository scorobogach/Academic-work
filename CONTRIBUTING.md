# Как участвовать

Спасибо. Проект маленький и задуман как инструмент, который можно целиком
прочитать за вечер, — пожалуйста, помогайте сохранять это свойство.

## Что особенно нужно

| Область | Что полезно |
|---|---|
| **Словари стиля** | Новые шаблонные обороты для `config/style-rules.ru.json` — **с примером из реального текста** и указанием дисциплины |
| **Парсеры** | Поддержка Word (`.docx`), Markdown-таблиц, `biblatex`, кириллических BibTeX-записей |
| **Гейты** | G4 (verbatim-diff цитаты против PDF), экспорт реестров в CSV/Markdown, canary-генератор |
| **Документация** | Примеры реальных прогонов, перевод кратких версий на английский |
| **Ошибки** | Минимальный воспроизводимый пример: файл + команда + ожидание/факт |

## Правила

### 1. Только стандартная библиотека

Ядро (`scripts/academic_journal/`, `scripts/mcp_server.py`, `scripts/journal_cli.py`)
должно работать без установки чего-либо. Исключения допустимы только в
отдельных опциональных скриптах и должны быть явно оговорены.

### 2. Тесты обязательны

```bash
make test                 # 40 тестов
python3 -m unittest discover -s tests -v
```

Новая проверка в гейте — минимум два теста: «ловит плохое» и «не трогает
хорошее». Второе важнее: ложные срабатывания убивают инструмент быстрее,
чем пропущенные находки.

### 3. Новое правило стиля — только с обоснованием

В PR укажите: реальный пример фразы, почему она шаблонная, в какой дисциплине
это так. Правило без примера почти наверняка будет стрелять по нормальному
тексту. Проверьте себя: добавьте правило и убедитесь, что `examples/minimal/main.tex`
по-прежнему проходит G1.

### 4. Никакого кода под CC BY-NC и без лицензии

`Imbad0202/academic-research-skills` — CC BY-NC 4.0, его файлы нельзя включать
в этот репозиторий. `citation-audit` и `webcite-mcp-server` не имеют лицензии.
Можно: ссылаться, описывать, делать совместимые форматы. Нельзя: копировать.
См. [NOTICE.md](NOTICE.md).

### 5. Не коммитим личные данные

Журнал, БД, отчёты гейтов, рукописи и сырые данные — вне репозитория
([.gitignore](.gitignore), [docs/privacy-and-legal.md](docs/privacy-and-legal.md)).
В issue и PR не вставляйте фрагменты реальных рукописей и персональные данные.

### 6. Формат коммитов

Коротко, в повелительном наклонении: `добавить гейт G5 для таблиц`,
`исправить разбор кириллических BibTeX-ключей`. Ссылайтесь на issue.

## Чек-лист перед PR

- [ ] `make test` проходит
- [ ] `python3 scripts/check_links.py` — ссылки целые
- [ ] новые правила стиля снабжены примерами
- [ ] документация обновлена (если меняется поведение)
- [ ] в PR нет личных данных, журналов и БД
- [ ] если меняется формат журнала — инкрементирована версия `v` и описано миграционное правило

## Чего мы не принимаем

- инструменты для удаления водяных знаков и маркеров происхождения;
- средства обхода AI-детекторов для учебных и научных работ;
- код, единственная задача которого — «сделать так, чтобы не нашли»;
- изменения, добавляющие внешние зависимости в ядро без очень веской причины.
