# Политика безопасности

## Что считается инцидентом

- утечка содержимого журнала диалогов или БД (там могут быть персональные данные,
  неопубликованные результаты, персональные данные респондентов);
- возможность модификации журнала без нарушения хеш-цепочки;
- выполнение произвольного кода через MCP-инструменты;
- утечка ключей API через конфиги агентов.

## Как сообщить

Откройте **private security advisory** в разделе Security этого репозитория
(или напишите напрямую мейнтейнеру), не публикуйте детали в issue.
Ожидаемый ответ — в течение 7 дней.

## Базовые правила использования

1. **Журнал и БД не публикуются.** Каталоги `~/.academic/`, `journal/`, `*.db`
   внесены в `.gitignore`. Проверяйте `git status` перед коммитом.
2. **Секреты — только через окружение.** В MCP-конфигах хранятся пути и имена
   переменных, но не значения ключей. Пример безопасного подхода —
   `anti-ai-slop`, который сохраняет *источник* ключа (`env:`, `keychain:`,
   `op://`), а не сам ключ.
3. **Проверяйте целостность.** `make journal-verify` должен быть частью рутины
   перед сдачей работы; расхождение цепочки — сигнал разобраться, а не
   «перезаписать файл».
4. **Персональные данные.** Если в журнал попали данные участников исследования,
   применяйте политику минимизации: срок хранения, шифрование at rest,
   удаление по требованию ([docs/privacy-and-legal.md](docs/privacy-and-legal.md)).
5. **Сторонние MCP-серверы.** Подключайте только те, кому можно передать текст
   рукописи. Облачные сервисы проверки цитат получают ваш неопубликованный текст.
